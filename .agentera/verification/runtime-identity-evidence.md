## Equality and authority in current KTX

Identity normalization (`internal/identity/identity.go:29-63`): validate UTF-8; trim ASCII edge whitespace from all tuple fields; lowercase only the runtime; preserve native session/call bytes and case; reject empty fields. Length-prefix each field under domain `ktx-tool-call-id-v1`, SHA-256, then map into the existing 16-lowercase-letter KTX ID domain.

`PersistToolCallOnce` equality compares `tool`, strict-canonical input evidence, output bytes, and optional `runtime` for an existing eligible ID. Strict canonicalization preserves number lexemes, rejects duplicate decoded object names and lone surrogates into exact-byte fallback, orders object names by UTF-16 code units, and preserves array order.

| Field/change                                                         | Current treatment                                                                             | Evidence consequence                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native runtime/session/call tuple                                    | Authoritative identity input before persistence                                               | Complete trusted tuple derives ID; tuple change means another ID. Native session/call are not stored separately.                                                                                                                                                                                              |
| `tool`, serialized `input`, `output`, `runtime`                      | Authoritative equality fields                                                                 | Any difference conflicts; first row stays authoritative.                                                                                                                                                                                                                                                      |
| Semantically equivalent JSON formatting in input                     | Compared through shared strict canonical JSON                                                 | Insignificant whitespace, object ordering, and equivalent string escaping converge; exact number lexemes remain distinct; invalid or duplicate-key JSON falls back to exact UTF-8 bytes.                                                                                                                      |
| `content_hash`                                                       | Ignored on retry                                                                              | First persisted hash remains. New hash neither enriches nor conflicts.                                                                                                                                                                                                                                        |
| `timestamp`, `event_type`                                            | Ignored on retry                                                                              | First values remain; retry does not update session `last_seen_at`.                                                                                                                                                                                                                                            |
| `session_id` (KTX association)                                       | Ignored by equality                                                                           | First source row owns the association; a retry linked to another KTX session neither moves nor enriches it. Native session identity remains a separate concept.                                                                                                                                               |
| `tokens_in`, `tokens_out`, `cost`, `latency_ms`, `model`, `provider` | Ignored on retry                                                                              | No enrichment occurs. Write-time cost derivation may mutate the incoming candidate before the ignored comparison, but the first persisted values remain.                                                                                                                                                      |
| `exit_code`, `is_error`                                              | Ignored on retry                                                                              | No enrichment or conflict; first values remain even if later delivery differs.                                                                                                                                                                                                                                |
| Pipeline/configuration change                                        | Ignored for source equality; the first persisted compressed row is authoritative once present | A transform and passthrough delivery may overlap. A retry that checks before any artifact exists may safely return source output. Once one artifact is persisted, no retry can replace it and subsequent retries return it even when their current pipeline is passthrough or computes a different candidate. |
| Changed compressed candidate under same source                       | First persisted artifact wins; candidate is ignored                                           | No compressed conflict is reported. Concurrent tests prove one row, not semantic equality.                                                                                                                                                                                                                    |

Thus current KTX has no enrichment class in its retry-safe write: fields are authoritative/conflicting or ignored/first-wins. Cost/token/error/exit additions are ignored, not merged. Pipeline behavior is internally split and cannot be described as fully first-wins until Task 2 resolves delivery authority.

## Historical compatibility

Current schema (`internal/db/schema.go:29-91`) stores opaque `tool_calls.id`, KTX `session_id`, evidence fields, and nullable `runtime`. It does not store native session ID or native call ID. Existing compressed rows reference the opaque source ID by foreign key.

The runtime migration test proves older rows gain `runtime=NULL` without rewriting IDs or evidence (`internal/db/runtime_migration_test.go`). Historical native tuples cannot be reconstructed from retained data, and no mapping should be proposed.

Conclusion: no historical row rewrite or schema migration is necessary for coexistence. New derived IDs fit the existing primary-key and foreign-key shape. Historical references remain valid. The derived and random IDs intentionally share the same public KTX domain, so a theoretical random/derived primary-key collision is handled by existing retry equality/conflict logic rather than an alias table.

Cross-version duplication limit: an old observation replayed after deterministic adoption can coexist once under its legacy random ID(s) and once under the new canonical tuple-derived ID. KTX cannot deduplicate or bound already-retained legacy duplicates because their native tuples were not stored. After adoption, eligible deliveries of that complete tuple converge to one canonical source row; ineligible/incomplete deliveries remain fresh observations by design.

## Retained unknowns and resolved implementation questions

1. Neither pinned runtime source guarantees native tuple stability under automatic failed-hook retry because neither inspected dispatcher implements such retry.
2. Callback replay and tuple stability across process/session restart are not guaranteed by inspected OpenCode or Codex contracts.
3. Model-requested re-execution is expected to receive a new native call ID, but inspected sources do not state a global uniqueness/stability guarantee.
4. Resolved after cycle 35: retry input equality uses strict canonical JSON with exact-byte fallback.
5. Resolved after cycle 35: later metadata remains first-wins with no enrichment.
6. Resolved after cycle 35: the first compressed artifact is authoritative once persisted; a concurrent retry may return source output only during the transient no-artifact-yet window.
7. Resolved after cycle 35: OpenCode hook and wrapper share trusted tuple resolution and normalized evidence persistence.
