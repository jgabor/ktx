# Changelog

## [Unreleased]

### Added

- `ktx hook --runtime claude-code` accepts Claude Code 2.1.304 `PostToolUse` payloads: trusted calls get deterministic identity and explicit success (interrupted calls stay unknown), and compressed Bash `stdout` returns through `updatedToolOutput` with every other `tool_response` key unchanged. Background, image, interrupted, and non-string results pass through without running the pipeline.
- `ktx init claude` generates a local Claude Code plugin marketplace with one `ktx` plugin: a Bash `PostToolUse` hook and a mod that shows a band above the prompt and a `/ktx` pane of compression figures for all runtimes. The pane opens again in the next interactive session when it was left open. ktx never edits Claude Code settings; `--show` reports staleness from a generated marker and `--uninstall` removes only generated files. `mage install` refreshes the folder, and `mage claudePluginCheck` runs `claude plugin validate` and `claude plugin test` on the generated plugins.
- `ktx optimize` adds offline screening, explicit 24-launch controlled live qualification, outcome inspection, and conflict-checked preview/apply/rollback with private originals. Only `pipeline.default.stages` may change; generated-only results remain ineligible. Targets that apply cannot replace exactly (symlinked paths, extra hard links, other owners, special mode bits) block during screening, before paid qualification. Command-prefix, subcommand, and other-tool routes are admitted unchanged while no controlled or retained qualification call selects them; their profiles need only valid built-in stages.
- `ktx doctor` now reports informational database/WAL/SHM file sizes with observed, absent, and unavailable states, and points to `ktx db report` for record totals and logical payload bytes without running aggregates or cleanup.
- `ktx doctor` now reports static pipeline configuration validity, ordered route-to-profile mappings, stage warnings, and effective plugin overrides without executing stages or changing configuration; existing database-readiness behavior is preserved.
- Active benchmark inputs now use one explicit semantic registry, and new experiment manifests retain archive-relative byte snapshots and SHA-256 identities for source-independent validation and regeneration.
- A zero-call qualification freeze binds the recovery-aware midfile matrix, aggregate paid ceilings, runtime identities, pricing, and fail-closed preflight evidence before execution.
- Experiment summary generation, validation, ranking, and rendering share a structured Go contract for current archives.
- Current benchmark summaries retain cue-linked recovery outcomes and exact normalized tool-call repeat counts from isolated attempt databases without exposing call material.
- Recovery-aware comparisons use methodology v7 and summary schema 7 to rank quality-qualified configurations by complete runtime total tokens per correct task while retaining separate recovery, repeat, delivery, cost, quality, stream-call, and persisted-call authorities.
- `ktx bench screen` now evaluates explicit complete pipeline configurations over one frozen generated population without model or database access, emitting bounded aggregate reconciliation and a controlled-fact-gated shortlist.
- `mage schemaReleaseGate` now blocks schema releases unless the exact prior physical schema passes the retained 3.2 GB scale, generated-adapter concurrency, interruption/restart, correctness, and approved combined-workload limits. Memory is aggregate concurrent KTX RSS, with per-process peaks retained separately.
- The schema-readiness contract now requires automatic preparation for every supported stale database surface, single-owner timeout attribution, and reproducible controlled-host resource gates with a retained raw baseline and disposable fixture harness.
- Schema 14 adds explicit OpenCode collection evidence for hook-owned delivery, wrapper-owned runtime timing and lifecycle, acknowledged recovery cues, linked byte-exact recovery attempts, and the read-only `ktx stats live-validation` fixed-window report. Ordinary `ktx run` behavior remains unchanged.
- Schema 13 retains metadata-only `run` ingress collection scope and lifecycle closure evidence. Continuity qualification reports explicit gaps for missing closure, interruption, conflict, pre-deployment history, and unelapsed windows; after readiness, evaluation is read-only and does not migrate or backfill evidence.
- `ktx stats summary` schema 10 and `ktx stats breakdown` schema 4 report trusted-ingress agent-attribution coverage over the exact output-bearing call population; historical and unverified calls remain unknown, and empty coverage is null.
- New wrapper sessions record the launched executable as identified ownership; complete recognized OpenCode and Codex hooks can identify reused sessions, while compatibility input remains unknown and the first trusted identity wins.
- Schema 12 records session attribution authority separately from the existing agent label; historical labels remain readable and migrate as unknown.
- `ktx stats summary` schema 9 and `ktx stats breakdown` schema 3 report requested-window latency states, runtime provenance, measured coverage and time bounds, and millisecond distributions; unavailable latency remains null.
- Schema 10 preserves latency values while recording explicit measured, unknown, or malformed state, milliseconds, and runtime authority; migrated history remains non-authoritative.
- `view_image` uses an explicit empty passthrough profile by default, and the example configuration exposes the same route.
- Newly accepted source and artifact rows retain independent first-wins command provenance from the existing closed producer vocabulary. Schema 11 leaves historical provenance unknown and does not change content-only output.
- Optional `[logs]` configuration now makes one best-effort private typed JSONL append for database-unavailable diagnostics without changing stderr behavior.
- Current prompt-cache comparisons use methodology v6 and `cache-reuse-v2` to emit token-weighted summary schema 5; methodology v5, summary schemas 1–4, and `cache-reuse-v1` remain historical evidence.
- Schema-5 prompt-cache benchmark summaries now publish a fail-closed, quality-adjusted API-equivalent cost guard; valid rejected candidates remain evidence but are not recommended by rank.
- `ktx stats summary` schema 8 now token-weights `prompt_cache_token_hit_rate_pct` across all accepted providers and models under the supported runtime contract without changing the response shape. Measured zero remains zero, incomplete evidence remains null, and retained schema 6 summaries remain unchanged historical evidence.
- `mage engineeringVerify` retains component and real-process load reports plus a hash manifest. It requires load correctness, exact reconciliation, and supported-lock checks while keeping timing descriptive.
- Engineering verification now retains a separate blocked-decompression process report with output barriers, byte-exact output evidence, hook timing and outcome, participant classes, and exact storage reconciliation.
- Engineering reports now record first-class wall-clock timing, focused `ktx read` measurements, and a reproducible noise-aware comparison contract while preserving retained schema-1 evidence.
- Real-process load reports now compare matched writers-only and mixed-agent workloads with distinct sessions, exact reconciliation, supported failure rates, and actual and percentage contention penalties.
- A pinned developer hook-only contention workload uses the 4,096-byte seed-6001 fixture at concurrency 1/2/4/8/16/32. Its one warmup and five measured rounds per level produced 6 warmup and 30 measured labels, 378/378 completions, 36/36 reconciled rounds, zero observed failures, and exact totals of 378 sources, artifacts, dispositions, source producers, and artifact producers on disposable databases.

### Changed

- `ktx --version` reports the module version from Go build info, so a `go install github.com/jgabor/ktx/cmd/ktx@vX.Y.Z` build prints `vX.Y.Z` and an untagged build prints its pseudo-version. A build with no module version, such as `mage build`, prints `dev` instead of `0.1.0-dev`. A `-ldflags "-X …/internal/version.Version=…"` value still takes precedence.
- The generated OpenCode plugin now starts `ktx` through `node:child_process` and finds it with its own `PATH` search instead of `Bun.spawn` and `Bun.which`, so it runs under both Bun and Node. Its generated revision changes: run `ktx init opencode` (or `ktx init opencode --project`) again to refresh an installed copy (`mage install` refreshes discovered installs), and rebuild the benchmark image (a `ktx bench compare --preflight --build` run) so its plugin matches the binary.
- Development checks now run the generated OpenCode plugin tests on Node 22.18 or newer and keep a Bun generated-adapter gate. Mage resolves the real `node` and `bun` executables before it isolates `HOME` and passes them as `KTX_TEST_NODE` and `KTX_TEST_BUN`, so version-manager shims no longer break hermetic runs. CI installs Node 24 alongside Bun.
- Building from source now requires Go 1.26.10 or newer (was 1.26.5).
- Schema-readiness release evidence now lives in tracked `docs/evidence/schema-readiness/`; the release gate reads the historical failed report from there.
- Documentation is grouped into `docs/guides/`, `docs/reference/`, and `docs/reports/`; the former `benchs/` report moved to `docs/reports/`. `ktx init opencode` now points troubleshooting at `docs/guides/opencode-telemetry.md#troubleshooting`, `ktx bench export` help points at `docs/guides/pipelines.md`, and the read-description experiment reads its inputs from `docs/reports/normalization/`.
- The README now focuses on what ktx does, its results, and a quick start. Build, verification, and benchmark instructions moved to `docs/development.md`, and `docs/README.md` indexes every guide, contract, and report.

### Removed

- `ktx bench agent`, `ktx bench compare`/`rank`, and `ktx optimize --live` no longer reject `github-copilot/*` models; every `provider/name` model is accepted.

### Fixed

- Live-validation uses a provenance-free seven-case matrix at the existing path with a new exact pinned digest; previous matrix identities are no longer accepted.
- Normal benchmark capture now uses private stdout and stderr spools, aggregate-only usage interpretation, and verified recording publication; failed or over-limit last copies remain owner-recoverable without changing scoring or replay limits.
- Optional OpenCode telemetry now releases acknowledged persistence payloads while retaining exact evidence for duplicate suppression and conflict detection.
- Codex hook updates now coordinate shared-document mutations, publish complete replacements, detect observed external edits, and recognize relocated generated commands without deleting unrelated hooks or metadata.
- Newline-heavy compression avoids whole-input line arrays, empty pipelines skip JSON recognition, and route selection reuses lazily extracted command metadata without changing output or matching behavior.
- Exact-match experiments now use retained stream/database authority with methodology `v8-exact-match`, attempt schema 3, and summary schema 8. Retired experiment readers and the inactive cache probe are removed; tracked history remains unchanged without current-validation guarantees.
- Long-lived database writers now reject newer schemas before evidence mutation, and queries recheck schema compatibility after reopening from automatic readiness.
- Benchmark execution and validation now share captured pipeline configuration identities, and capability probes plus both comparison sides use the full immutable image ID resolved by preflight rather than a mutable tag.
- Owned command values no longer become help or format flags; namespace options support consistent placement, explicit false help and local format precedence. `ktx write` now reports acknowledgement delivery failure without rolling back committed evidence.
- `ktx run` now resolves wrapper flags once, honors explicit false values before and after the executable, and preserves literal child arguments after an explicit `--` boundary.
- `ktx bench run` now binds results to the completed wrapper's explicit session, never substitutes concurrent or historical sessions, and reports startup or interrupted collection failure without recording a false headline or replay.
- Experiment archive reads now reject traversal and escaping symlinks before access, and SQLite inspection uses private copies of confined database and WAL files without opening or migrating archive originals.
- Experiment summarization and validation now reject incomplete entry contracts and empty evidence, exclude damaged declared artifacts from target counts, and preserve inspection of incomplete archives.
- Active cache sequence, estimation, statistics, regeneration, and comparison code now has a separate package boundary from retired direct-provider probes.
- Recovery-aware validation now accepts target-met archives with unavailable auxiliary outcomes, and live comparisons can pin exact retained pricing bytes before any model attempt.
- Recovery-aware benchmark summaries now pair stream-derived source identities with persisted rows inside each attempt and expose separate counts, coverage, duplicate/retry observations, and bounded discrepancy reasons; unavailable authority remains null and stream-only failures are not converted into persisted outcomes. Schema-6 reports remain static history.
- Incomplete recovery-aware experiments now retain a structurally valid unavailable comparison and unmet-target reason; validation keeps historical partial summaries immutable and labels derived inspection separately.
- Required benchmark collection now retains delivered recovery cues and exact linked recovery attempts under the precreated interval owner; older archives without cue authority report recovery as unavailable.
- Recovery-aware comparison now leaves unavailable outcomes unranked, renders their state and reason, and validates generated schema-7 archives against methodology v7.
- `mage install` now refreshes already-enabled global and current-project OpenCode and Codex adapters after installing the development binary, preserves unrelated Codex hooks, and fails with an exact recovery command for every scope that does not refresh.
- Current user and agent guidance now consistently describes automatic stale-schema readiness, post-readiness read-only queries, forward-only newer-schema failure, isolated verification, and the separate production-scale schema release gate.
- Query, doctor, telemetry, hook, recovery, and retained-artifact inspection paths now prepare existing supported older databases automatically, then use read-only access where required. Missing-database, current-schema, newer-schema, coordination, and timeout contracts remain unchanged.
- Schema 15 preparation now uses an atomic primary-key cursor for bounded compressed-timestamp batches, populates sortable timestamps on every artifact write path, resumes after process termination, and publishes schema 16 without a data-sized final index build.
- Generated `ktx.ts` callbacks no longer kill KTX after 10 seconds; `ktx hook` retry preflight now uses writer-preferred coordination and stable `database-unavailable` attribution.
- `ktx run` now rejects an explicit empty `--record-stream=` value while preserving supported boolean and numeric forms and child arguments.
- Plugin commands now reject malformed configuration without mutation, and durable configuration, price-cache, report, experiment, preflight, and replay-fixture updates publish complete same-directory replacements without treating temporary files as authority.
- Current-schema hooks now fast-open without exclusive coordination, fall back to coordinated creation or migration, then revalidate schema under writer ownership and keep ordered source, artifact, and disposition commits inside one exclusive coordination window. A concurrent upgrade fails closed before hook evidence writes, while complete exact retries and pre-source rejections remain read-only.
- Database-unavailable diagnostics now identify the callback surface, pinned executable, database target, stable failure class, operation phase, elapsed wait, and observed Linux coordination blockers without exposing driver text or persisted content.
- Linux coordinator-timeout diagnostics now label verified supported blocker commands from a closed vocabulary and report all uncertain identities as `unknown`.
- Supported read-only database handles now coordinate with writers, and supported writers coordinate each SQLite transaction across processes.
- OpenCode ordinary telemetry and hook callbacks now share one arrival-order queue, and each write-capable database handle uses one process-local SQLite connection.
- SQLite lock exhaustion now returns `database-unavailable` with the canonical database path and retry guidance instead of driver lock diagnostics.
- `ktx read` now releases supported read ownership after retrieving a record, so blocked output no longer delays an unrelated supported writer.
- `ktx hook` now takes delivery footer policy from the selected retained artifact's recorded structured-recovery provenance. Exact retries preserve repaired JSON and NDJSON validity and ordinary retained-artifact footer behavior; legacy artifacts without provenance remain readable and keep conservative behavior without inferred reconstruction.
