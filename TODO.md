## Completed foundations

- [x] **Indexed recent stats windows** — Schema 15 stores sortable nanosecond epoch forms of valid tool-call and session-telemetry timestamps and indexes bounded stats selectors. `stats`, `stats summary`, and `stats breakdown` preserve inclusive UTC and offset boundary behavior, output values, and malformed-timestamp exclusion. Focused selector tests and the repository-wide check passed under a disposable application root. → [Measurement](ARCHITECTURE.md#measurement)
- [x] **Writer-preferred supported coordination** — Supported ktx processes coordinate admission and ownership on the physical database file so a waiting writer runs before later readers. Linux uses byte-range admission with ownership locking; BSD and Windows use separate ranges. Linux ordering and combined stats/write workloads passed; BSD semantics were tested and compile-checked but not natively executed. Read-only commands create no coordination state. → [I/O and query separation](ARCHITECTURE.md#io-and-query-separation)
- [x] **Single-window hook coordination** — Current-schema hooks parse, load configuration, derive cost, and transform before one exclusive coordination window; source, artifact, and disposition remain separate ordered durable commits inside it. Fast-open falls back to coordinated creation or migration. A schema recheck under writer ownership rejects concurrent upgrades before hook writes. Complete exact retries and pre-source rejections remain read-only, and final source validation preserves first-wins source, artifact, and producer evidence across preflight races. → [Ingress](ARCHITECTURE.md#ingress)
- [x] **Single pipeline resolution per operation** — Hooks and database replay load configuration once per operation and resolve profile, route provenance, stages, timeout, and recovery settings through one path. The stage contract and portable replay remain unchanged. → [Pipeline](ARCHITECTURE.md#pipeline)
