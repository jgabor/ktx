# Claude Code integration

This guide shows how to connect ktx to Claude Code: install the plugins, see
what they compress and show, and fix common problems. One plugin compresses
Bash output before Claude reads it. A second plugin, a mod, shows ktx's
savings in a status line and a `/ktx` pane.

ktx targets the Claude Code 2.1.304 hook and plugin contract, and both
generated plugins pass `claude plugin validate --strict` on that version. The
mod needs Claude Code 2.1.287 or newer. Its API is still early access, so a
later Claude Code release can change it.

## Install

`ktx init claude-code` writes a small local plugin marketplace to
`$XDG_DATA_HOME/ktx/claude-code/marketplace` (or
`~/.local/share/ktx/claude-code/marketplace` when `XDG_DATA_HOME` is unset).
ktx never edits your Claude Code settings. You register the folder once
yourself:

```bash
ktx init claude-code
claude plugin marketplace add ~/.local/share/ktx/claude-code/marketplace
claude plugin install ktx@ktx-local
claude plugin install ktx-stats@ktx-local
```

The install output prints these commands with your real folder, quoted for the
shell. Start a new Claude Code session, or run `/reload-plugins` in an open
one.

The marketplace holds two plugins:

| Plugin      | What it does                                                          |
| ----------- | --------------------------------------------------------------------- |
| `ktx`       | A `PostToolUse` hook for the Bash tool that compresses its output     |
| `ktx-stats` | A mod that polls `ktx stats summary` and shows a status line and pane |

Both plugins pin the canonical path of the ktx binary that generated them. The
hook runs that path in exec form, with no shell, as
`<ktx> hook --runtime claude-code`, and sets no timeout. A later `PATH` change
can't switch either plugin to a different binary.

Claude Code reads both plugins from the folder itself. After you upgrade or
move ktx, run `ktx init claude-code` again, then run `/reload-plugins` in
Claude Code (or restart it). Install is idempotent: a run that changes nothing
rewrites nothing. `mage install` refreshes the folder for you when it finds
one.

`ktx init claude-code --show` reads the generated `.ktx-generated.json` marker.
It reports whether the files are stale: generated by another ktx version,
edited, missing, or pinned to a ktx binary that no longer exists. It can't tell
whether Claude Code registered or loaded the plugins. There is no `--project`
scope for Claude Code.

## What gets compressed

Only Bash calls, and only their standard output. ktx stores the original,
runs your pipeline, and hands Claude a copy of the tool result with `stdout`
replaced. Every other field stays as Claude Code sent it. Routes in
`ktx.toml` match these calls with `tool = "Bash"`, which is case-sensitive.

ktx leaves a call unchanged and records it as passthrough when it can't
replace the output exactly: a background command, an image result, an
interrupted call, or output that isn't plain text. Failed calls
(`PostToolUseFailure`) are not recorded yet. If the hook fails, Claude reads
the original output.

When a lossy profile sets `recover_footer = true`, Claude sees the usual
one-line hint with the `ktx read <id>` command that returns the original.

## Status line and /ktx pane

The `ktx-stats` mod runs `ktx stats summary --window 15m --format json` every
10 seconds through the pinned binary, with a 5 second timeout. It shows one
line under the prompt:

```text
ktx 15m: 46% saved · 1.2M→650k tok · 120/300 calls
```

That reads as: 46% of the raw output tokens were saved, 1.2 million raw tokens
became 650 thousand, and 120 of 300 calls with output had a compressed copy.
With no calls in the window it shows `ktx: no calls in 15m`. If a refresh
fails, the mod keeps the last good figures and marks them `(stale)` until a
later refresh works.

Type `/ktx` to open a pane with the same figures: saved tokens and percent, a
bar, raw and delivered tokens, and compressed and total calls. Buttons switch
between the 15, 30, and 60 minute windows. The mod polls only in interactive
sessions, not in `claude -p` runs.

## Status line without the mod

If your Claude Code version has no mods, or you prefer your own status line,
add ktx to the `statusLine` command you already use. This snippet prints the
same saved share. It needs `jq`:

```bash
ktx stats summary --window 15m --format json 2>/dev/null | jq -r '
  if .calls.total_with_output == 0 then "ktx: no calls in 15m"
  elif .tokens.raw_estimated == 0 then "ktx 15m: — saved"
  else "ktx 15m: \(100 * (.tokens.raw_estimated - .tokens.delivered_estimated)
    / .tokens.raw_estimated | round)% saved" end'
```

Claude Code runs the status line command often, and each run reads the ktx
database, so keep the window short.

## Uninstall

Remove the marketplace from Claude Code, then remove the files:

```bash
claude plugin marketplace remove ktx-local
ktx init claude-code --uninstall
```

Removing the marketplace also uninstalls its plugins. `--uninstall` deletes
only the files listed in the marker, plus the `.claude-plugin/types/` folders
Claude Code may write into loaded plugins. Anything else in the folder stays,
and ktx prints a warning for each file it leaves.

## Troubleshooting

- Run `ktx init claude-code --show`. If it reports stale files, run
  `ktx init claude-code` and then `/reload-plugins`.
- Run `claude plugin list` to check that `ktx@ktx-local` and
  `ktx-stats@ktx-local` are installed and enabled.
- Start Claude Code with `claude --debug` to see hook runs and mod load errors.
- The status line and pane figures cover every runtime ktx records (OpenCode,
  Codex, Claude Code, and `ktx run`), not only the current Claude Code session.
- ktx doesn't collect model token or cost telemetry from Claude Code yet. Bash
  calls and their compression are recorded, but per-step model usage is not.
- If the status line says `unavailable`, run the same
  `ktx stats summary --window 15m --format json` command yourself to see the
  error.
- If the hook seems to do nothing, check that your pipeline config has a route
  for `tool = "Bash"`. Without a config file, output passes through unchanged.
